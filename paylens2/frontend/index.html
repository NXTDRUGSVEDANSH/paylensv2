What happens when you press return

  1. AuthorA model writes SQL from the schema card and retrieved examples.
  2. CheckViews only. No SELECT *. Metric formulas verbatim.
  3. GuardThe same nine checks the compiled pipeline passes.
  4. ExecuteRead-only, with a timeout and a row cap.
  5. ProfilePython measures the result into numbered facts.
  6. ComposeProse from the fact pack, then a grounding check.
  7. LearnThe query is kept as an unverified example.

Built in

Role-aware rows
A merchant account cannot read another merchant's rows. The filter goes into the SQL and is re-checked after injection.
No invented figures
Every number in the prose must appear in the measured fact pack, or the composition is discarded and the measured answer shown instead.
It asks back
When a question genuinely has two answers, you get the question that separates them — not a fixed metric picker.
Honest failure
A query that would not build says so. Only a missing concept is reported as missing from your data.
Charts that follow the data
The model proposes a chart before any row exists; the real result overrides it, and every override is printed under the chart.
Follow-ups
A later question inherits the period and filters of the one before it, and replaces what it states itself.
